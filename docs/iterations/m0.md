# M0 骨架

通用规范见 [conventions.md](conventions.md)。

## 目标与依赖

仓库、进程和基础设施按设计文档就位。这一步没有业务功能。

依赖：无。

## 范围与不做

做：单仓目录、四个 Kratos 应用、空的 `web`、`pkg` 中的错误码和 Redis 锁、`alioth` 的 ent 迁移入口。

不做：用户、Namespace、数据源、规则、通知、Agent。不建业务表。不把 Redis 用作缓存或队列。`megrez` 和 `merak` 不提供除 `/health` 以外的 HTTP。

## 开发细则

### 目录

按 [conventions.md](conventions.md) 建立 `api/`、`pkg/`、`app/alioth`、`app/megrez`、`app/merak`、`app/alkaid`、`web/`。根目录 `Makefile` 能分别构建和运行这五个进程。

每个后端应用：

- 独立 `go.mod`
- `replace` 指向 `../../pkg`（应用在 `app/<name>` 时）
- `cmd` 使用 Cobra
- `internal/server`、`internal/service`、`internal/biz`、`internal/data`、`internal/conf`
- `cmd` 下的 Wire 注入器可以生成并编译

`api/alioth/v1`、`api/megrez/v1`、`api/merak/v1` 先放健康检查和空的服务占位，生成代码能编译。业务 RPC 留到对应里程碑。

### 配置与端口

Bootstrap YAML 用环境变量占位。默认监听：

| 进程 | 配置项 |
| --- | --- |
| `web` | HTTP 8080。nginx 与 Vite 都把 `/v1` 转到 `alioth:8000` |
| `alioth` | HTTP 8000，gRPC 9000 |
| `megrez` | HTTP 8001 |
| `merak` | HTTP 8002 |
| `alkaid` | HTTP 8022，gRPC 9022。配置里预留 `alioth` gRPC 地址 `alioth:9000`，这一步可以不建立业务流 |

`alioth` 同时提供 `GET /health`。`megrez`、`merak` 的 HTTP 路由只注册 `/health`。

### ent

`app/alioth/internal/data` 连接 PostgreSQL，并提供迁移命令。schema 可以为空，迁移命令必须能对空库执行成功。`megrez`、`merak`、`alkaid` 的配置里没有业务库 DSN，代码里不导入 ent client。

### Redis 锁

在 `pkg` 实现锁客户端，供以后的 `alioth`、`megrez`、`merak` 使用。这一步用测试覆盖协议，不接入评测或投递。

- 加锁：`SET key token NX PX ttl`，`token` 为 `{instance_id}:{random}`
- 续期：Lua 在 value 等于 token 时 `PEXPIRE`
- 释放：Lua 在 value 等于 token 时 `DEL`
- Redis 不可用时返回错误，调用方不得把这次操作当成成功

测试使用真实 Redis 或测试专用实例，不用进程内假锁代替这组用例。

### Web

`web` 是一个 Vite + React + TypeScript + Tailwind + shadcn/ui 应用。首页能打开。`web/src/api` 放置 HTTP 客户端，base URL 为 `/v1`，组件不直接引用 axios。开发代理只指向上游 `http://127.0.0.1:8000`。

## 本步规范

- 新文件放进上表目录，不在仓库根随意增加服务。
- 共享代码进 `pkg`。应用之间不互相 import `internal`。
- 端口写在配置里，不在业务代码中写死第二套端口。
- 锁的 Lua 脚本和 token 比较放在 `pkg`，应用不各自实现一套 `SET NX`。

## 验收标准

- [ ] `alioth` 的 HTTP 在 8000、gRPC 在 9000，`GET /health` 成功。
- [ ] `megrez` 在 8001 提供 `/health`。8001 上的其他路径没有管理接口。
- [ ] `merak` 在 8002 提供 `/health`。8002 上的其他路径没有管理接口。
- [ ] `alkaid` 同时监听 HTTP 8022 和 gRPC 9022。
- [ ] `web` 在 8080 打开页面。浏览器请求 `http://<web>:8080/v1/health` 到达 `alioth:8000`，不到达 8001、8002、8022、9022。
- [ ] 锁测试包含：首次加锁成功、第二进程加同一键失败、持有者续期成功、错误 token 不能释放、Redis 不可用时调用方得到错误。
- [ ] 执行一次 ent 迁移后，PostgreSQL 里没有 `megrez`、`merak`、`alkaid` 创建的表。
- [ ] `go test` 覆盖 `pkg` 锁客户端，五个进程都能编译。
