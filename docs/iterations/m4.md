# M4 天璇通知

通用规范见 [conventions.md](conventions.md)。

## 目标与依赖

告警和页面试发都变成任务，由 `merak` 投递邮件或 Webhook。

依赖：M3。

## 范围与不做

做：渠道、模板、通知组、告警订阅、任务、消息日志、`merak` 投递、试发。

不做：短信发送。`SMS_ALICLOUD` 可以出现在枚举中，没有客户端，也不能把任务报成 SENT。不在 `merak` 进程里同步等待 SMTP 来完成浏览器请求。规则不直接绑定通知组；事件统一由告警订阅路由。

## 开发细则

### 数据

在 `alioth` 增加：

| 实体 | 要点 |
| --- | --- |
| `NotificationChannel` | SMTP，或 Webhook。Webhook 应用为 OTHER、DINGTALK、WECHAT、FEISHU。密码和签名加密存储 |
| `NotificationTemplate` | 按消息类型保存正文。首期类型为 EMAIL 与四种 WEBHOOK |
| `NotificationPreset` | 系统预置模板，只读。用户可直接使用，或修改后生成自己的模板 |
| `NotificationGroup` | Namespace 内的接收方集合，关联主渠道/模板、成员和多个 Webhook 渠道，可启停 |
| `NotificationSubscription` | 按标签、告警级别和数据源订阅事件，命中后发送给订阅下的通知组 |
| `NotificationTask` | 状态 PENDING、SENDING、SENT、FAILED、CANCELLED。记录剩余重试次数 |
| `MessageLog` | 一次投递的结果。按时间做声明式分区 |

`AlertRule` 不保存通知组。M2 预留的通知组编辑位置在本步移除；事件路由由 `NotificationSubscription` 负责。

同一告警事件、同一通知组、同一渠道只生成一条等效任务。FIRING 与恢复各算一次，互不占用。去重用 PostgreSQL 唯一约束，不放进 Redis。

### 状态机

1. 评测回写 FIRING 或恢复时，`alioth` 在同一事务内匹配告警订阅，按订阅下的通知组生成 PENDING 任务。
2. 页面试发也生成 PENDING 任务，不在请求线程里连接 SMTP。
3. `merak` 读取 PENDING 任务，先对 `alioth:lock:notify:{task_uid}` 加锁，TTL 60 秒，每 20 秒续期。没拿到锁则跳过。
4. 持锁后请 `alioth` 把任务改为 SENDING，渲染模板，调用 SMTP 或 Webhook。
5. 回写 SENT 或 FAILED，并写 `MessageLog`。失败且仍有剩余次数时回到 PENDING。次数耗尽后停在 FAILED。
6. 释放锁。续期失败时不回写成功。
7. 页面可以重试 FAILED 任务和取消尚未成功的任务。取消后的状态是 CANCELLED，`merak` 不再领取。

### merak

`api/merak/v1` 由 `alioth` 实现。`merak` 使用自己的 service key 领取任务和回写。领取响应包含渠道、模板和接收方，其中的密钥只用于当次投递。

`merak` 的 HTTP 只有 8002 `/health`。用户 JWT 不能领取任务。

### Web

页面：通知渠道、模板、通知组、告警订阅、消息日志。模板页提供“预设模板”，从预设创建时会生成一条可编辑的自定义模板。

渠道和模板支持启停。消息日志支持查看、重试、取消。试发入口放在渠道或模板上，提交后列表里出现任务，由 `merak` 改变状态。

## 本步规范

- 模板渲染放在 `merak`。`alioth` 保存模板原文和任务参数。
- 投递超时后回写 FAILED，不让 SENDING 永久停留。超时时间写在配置里。
- 日志不打印 SMTP 密码、Webhook 签名和完整令牌。
- 短信枚举若出现在界面，提交后给出未实现，不创建一条会被报成 SENT 的任务。

## 验收标准

- [ ] 一条 FIRING 对同一通知组、同一渠道只生成一条 `NotificationTask`。恢复另外生成一条，不与 FIRING 任务重复。
- [ ] 两个 `merak` 同时运行。同一任务只有一个副本发送成功，`MessageLog` 只有一次成功记录。
- [ ] 邮件和四种 Webhook 各成功投递一次。选择短信类型时没有发送实现，任务不会变成 SENT。
- [ ] 渠道地址不可达时任务变为 FAILED，并按剩余次数回到 PENDING。次数耗尽后停在 FAILED。页面上可以重试和取消。
- [ ] SMTP 渠道只能绑定 EMAIL 模板，Webhook 渠道只能绑定 WEBHOOK 模板；不匹配时保存和试发都被拒绝。
- [ ] 钉钉、飞书配置签名后，投递请求包含正确签名；企业微信检查 `errcode`，非 0 不报 SENT。
- [ ] 从预设模板直接使用或修改后保存，都会生成当前 Namespace 的自定义模板，预设本身不被修改。
- [ ] 在 `http://<web>:8080` 试发。产生的是 `NotificationTask`，状态由 `merak` 更新。浏览器请求在任务入库后返回，不等待 SMTP。
- [ ] 渠道密码和 Webhook 签名在库里是密文，接口回显不是明文。
- [ ] `merak` 的 8002 仍然只有 `/health`。用户 JWT 领取任务被拒绝。
- [ ] 停用的订阅或通知组不会再为新的 FIRING 生成任务。
- [ ] 通知组可以选择当前 Namespace 的成员和多个 Webhook 渠道，至少一个接收目标。
