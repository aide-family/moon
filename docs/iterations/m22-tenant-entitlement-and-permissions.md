# M22 租户权益快照、多币种与菜单化授权

M22 修复套餐细化后暴露的六个问题，核心是两条：**套餐编辑不能反向改变已生效租户的权益**，**权限配置必须按菜单组织且菜单默认带读权限**。同时补上多币种定价、能力说明和几处展示/加载缺陷。

依赖：M19（能力模型）、M20（套餐定价与订单）、M21（类型级能力与租户升级续期）。

## 1. 可选模块的 403 不再打翻整页

告警规则页会一次性加载等级、数据源和探测目标组。当套餐没有 HTTP 探测能力时，探测目标组接口返回 403，前端全局 403 拦截把页面重定向到 `/forbidden`，即使规则本身有权访问。

处理：规则页、数据源页、成员页、告警订阅页的跨模块选择器在加载前按当前权限判断（`session.can` / `hasFeature`）；没有对应模块时跳过请求，保留空选择器。页面主数据仍由各自菜单权限控制；直接访问无权限页面仍走 403 跳转。

## 2. 租户套餐授权快照

**问题**：租户能力实时读套餐明细，管理员修改套餐后，已生效租户的授权随之变化，权限页与实际菜单出现不一致；在权限页原样保存还可能把旧授权静默丢掉。

**模型**：`namespaces.package_features` 保存租户购买/换套餐时的能力快照。

- 新建租户、升级换套餐、平台给租户改派套餐时写入新套餐当前明细的快照；
- 续期不改变快照；之后管理员编辑套餐内容不影响已生效租户；
- 生效能力与权限页都读快照；新租户读取套餐当时的明细；
- 同一套餐下只允许调整额外能力：目标能力必须包含租户快照，套餐外能力可加可减；
- seed 增加 `migrateNamespacePackageSnapshots`，给升级前的租户补快照（使用当时的套餐明细），可重复执行。

角色权限页另外保留“套餐外的旧授权”分组：目录里已经不存在的权限会继续展示并默认保留，原样保存不会再静默撤销。

## 3. 永久套餐到期时间

后端在租户读取与功能状态里把 Unix `<= 0` 的 1970 占位时间按永久处理；前端所有套餐到期展示统一判断 `> 0`，0 显示“永久”，不再出现 1970/1/1。

## 4. 多币种定价

- `feature_packages.currency` 与 `namespace_orders.currency`：支持 `CNY`、`USD`、`EUR`、`JPY`，默认 `CNY`；
- 价格仍按币种最小单位（分）存储，下单时把币种与金额一起快照；
- 套餐后台价格输入框内嵌币种选择（符号 + 币种），列表、详情、租户套餐卡片、订单列表/详情和租户订单页都按订单/套餐币种展示符号；
- 业务校验拒绝目录外币种，proto 同步约束。

## 5. 能力说明 tips

套餐能力勾选器的每一项增加 `Info` 图标和 Tooltip，内容来自能力目录的 `description`（中英随界面语言），说明功能场景；不再把说明文字平铺在行内。

## 6. 角色权限按菜单组织

角色权限页的第一级不再是套餐能力，而是**菜单**：`pkg/perm/menu.go` 维护独立菜单目录（31 个菜单），能力只负责回答「套餐是否开通这个菜单」。数据源 6 种驱动、通知渠道 3 种类型、探测 HTTP 共用各自的一个菜单，不再出现 6 张数据源卡。

- 菜单目录字段：`code`、分组、名称、可开通能力、子权限、默认读权限、是否固定菜单；
- `ListPermissions` 额外返回 `menus`（`PermissionMenu`），前端不再自行猜测菜单与权限的归属；
- 授权页按「分组 → 菜单 → 子权限」三级排版：
  - 勾选菜单即授予 `menu:<菜单>`，并默认带该菜单的读权限（`:read` / `:logs`），读权限行锁定并标记“默认读权限”；
  - 菜单下的写、删除、执行子权限必须先勾选菜单，否则不可选；
  - 每个菜单拥有独立的权限名：实时告警 `alert_realtime:*`、历史告警 `alert_history:*`、告警页面 `alert_page:*`、告警字典 `alert_dictionary:*`、通知渠道 `notification_channel:*`、消息模板 `notification_template:*`、通知组 `notification_group:*`、告警订阅 `notification_subscription:*`、OnCall `notification_oncall:*`、消息日志 `message_log:*`；在某个菜单下授权的写/删除不会扩散到同组其他菜单；
  - `namespace:*` 归入固定「租户设置」菜单，`namespace:read` 是该菜单的默认读权限；
  - 套餐外旧授权单独展示并默认保留，不再出现“无菜单归属”的可见权限；
- 后端 `normalizeRoleGrant` 统一执行三条规则：菜单补默认读权限；子权限补声明它的已开通菜单；owner-only 权限拒绝授予；
- `access` 的菜单校验：菜单被套餐开通且角色持有 `menu:<菜单>` 即放行；实时告警和历史告警共用的事件列表接口使用 `RequireAny` 同时接受两个菜单的读权限；
- 权限名与菜单一一对应，不再存在跨菜单共享动作，因此也不需要按“共享权限只归一个菜单”做特殊处理；
- **不做数据迁移**：本次权限名是破坏性变更，旧菜单权限和旧角色授权不兼容；seed 不再映射旧编码，测试环境直接清空表结构和数据后重建；
- 预置角色由 `RolePermissionsForCapabilities` 按已开通菜单补齐 `menu:*`，不再按能力逐个生成。

## 7. 套餐授权同步（全部 / 指定租户）

套餐编辑不影响存量租户后，管理员需要一个显式动作把套餐最新内容推给使用它的租户。套餐管理新增「同步授权」：

- `GET /v1/system/package/{uid}/namespaces`（`system:package:read`）列出正在使用该套餐的租户；
- `POST /v1/system/package/{uid}/sync`（`system:package:write`）`{namespaceUids}`：空列表表示全部使用该套餐的租户，非空只同步指定租户；
- 同步只覆盖 `namespaces.package_features` 快照，并给预置角色补齐新能力权限；额外能力、到期时间、价格和成员上限不变；
- 已经并入套餐的额外能力会从 `namespace_features` 清理，避免重复展示；
- 指定租户中没有使用该套餐或已删除的计入 `skipped`，不报错；
- 前端套餐行操作打开同步弹窗：选择「全部租户」或「指定租户」，指定模式默认全选，可逐个取消；结果提示同步/跳过数量。

## 验收

1. 只开通数据源能力、未开通 HTTP 探测时，告警规则页可正常打开，探测目标选择器为空，不跳转 `/forbidden`；成员页、订阅页在缺少角色/数据源权限时同样不跳转。
2. 修改套餐能力后，已生效租户的 `package_features`、有效能力和权限页保持不变；新租户使用修改后的套餐；同一套餐下租户可以加开或关闭额外能力。
3. 永久套餐在租户列表、租户页套餐卡片、功能授权弹窗都显示“永久”，不出现 1970/1/1。
4. 套餐可以设置为 CNY/USD/EUR/JPY，价格输入框内显示币种符号；订单和页面按快照币种展示金额。
5. 套餐能力每项有说明 tooltip。
6. 角色权限按「分组 → 菜单 → 子权限」展示；数据源/通知渠道只出现一张菜单；勾选菜单自动带读权限且读权限锁定；子权限不能脱离菜单提交；每个菜单权限名独立（例如在消息模板菜单下授权写权限不会获得通知渠道写权限）；`namespace:*` 归入「租户设置」；套餐外旧授权可见且默认保留。
7. 套餐「同步授权」支持全部或指定租户：指定同步只更新选中租户快照，全部同步覆盖套餐下全部租户，额外能力保留、已并入套餐的能力被清理，未使用该套餐的租户计入跳过。
8. 本次权限拆分不做数据迁移；测试环境已清空 `alioth_test` 的 schema 和数据后重新迁移、灌入种子数据。
9. `go vet`、后端单元测试、真库集成测试（套餐编辑不影响租户快照、同步指定/全部租户）、`gofmt`、`check-naming`、`buf lint`、`make wire`、api build/test、web typecheck/lint/build 通过。
