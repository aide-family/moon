# M5 摇光 SSH

通用规范见 [conventions.md](conventions.md)。

## 目标与依赖

Agent 出站上线。审核通过的 SSH 命令在指定机器上执行。

依赖：M1。不依赖 M2 到 M4。

## 范围与不做

做：Agent 令牌、出站流、心跳、机器信息、SSH 审核与执行、机器页面和命令页面。

不做：SFTP、Kubernetes 代理、探测任务。控制面不按 Moon 玉树的方式回拨 Agent HTTP。不把 8022 和 9022 挂到 Web nginx。

## 开发细则

### 数据

在 `alioth` 增加：

| 实体 | 要点 |
| --- | --- |
| `Agent` | Namespace、主机名、机器标识、本机 IP、版本、采集 JSON、在线状态、令牌哈希 |
| `SSHCommand` | 名称、命令、工作目录、环境变量。只有审核通过后才可执行 |
| `SSHCommandAudit` | 种类 CREATE / UPDATE，状态 PENDING / APPROVED / REJECTED。执行记录另含操作者、命令、退出码、输出 |

令牌明文只在签发时返回一次。库里保存哈希。吊销后该哈希作废。

机器信息字段对应 Moon 的 `machine_infos`：机器标识、主机名、本机 IP、Agent 版本、采集 JSON。在线状态由心跳维护，不再把「最近一次上报」当作心跳。

### 连接

`alkaid` 监听 HTTP 8022 和 gRPC 9022，供所在机器或集群内使用。业务会话是到 `alioth:9000` 的双向流。配置只有 `alioth` 的 gRPC 地址和 Agent 令牌。

流建立后发送注册：Namespace、令牌、主机名、机器标识。`alioth` 写入或更新 `Agent`，并标记在线。之后按固定间隔心跳，并上报机器信息。连接断开则标记离线。

目标 Agent 没有存活的流时，执行接口立即失败。`alioth` 不把命令放进进程内存队列。

吊销令牌后，下一次心跳时 `alioth` 关闭这条流。旧令牌不能再次注册。

用户 JWT 不能打开这条流。Agent 令牌不能调用 Namespace、用户、规则等管理接口。

### SSH

行为对应 Moon 玉树的审核流，执行点改到持有该主机的 `alkaid`：

1. 提交新建或更新，生成 PENDING 审计。
2. 通过或拒绝。通过后写入可执行的 `SSHCommand`。
3. 单条执行或批量执行。`alioth` 检查 `ssh:exec`，把命令帧送到指定 `agent_uid`。
4. Agent 在目标主机上执行，回传退出码和输出。
5. 每次执行写入审计。

未审核和已拒绝的命令不能执行。Moon 的按 endpoint 派发不实现，页面改为选择在线 Agent。

`alkaid` 使用目标主机的 SSH 凭据。凭据加密后存在 `alioth`，经流下发给当次执行，不写进 Agent 日志。

### Web

页面：机器列表与详情、SSH 命令、审计。机器页显示在线或离线。执行前必须选择在线 Agent。`viewer` 只能查看。

## 本步规范

- 命令执行的鉴权在 `alioth`。Agent 收到帧时默认已经过授权，仍要校验帧属于当前流的 Agent。
- 8022 与 9022 可以在本机健康检查，不写入 Web 的代理配置。
- 审计只追加。本步不提供删除审计的接口。
- 输出可以截断保存，截断长度写在配置里，并在审计中标明已截断。

## 验收标准

- [ ] `alkaid` 监听 8022 和 9022，并向 `alioth:9000` 建立流。从集群外访问 8022 和 9022 失败。`/v1` 不被反代到这两个端口。
- [ ] 流建立后，`http://<web>:8080` 的机器页显示在线。停止进程后变为离线。对离线 Agent 执行命令立即失败。
- [ ] 吊销令牌后，已建立的流在下一次心跳被关闭。旧令牌不能再次注册。新令牌可以注册。
- [ ] 未审核或已拒绝的命令执行被拒绝。通过后的命令在目标主机执行。审计含操作者、命令、退出码和输出。
- [ ] 没有 `ssh:exec` 的用户执行被拒绝。`viewer` 可以查看命令和审计，不能提交、通过或执行。
- [ ] 用户 JWT 不能打开 Agent 流。Agent 令牌调用 Namespace 或用户接口被拒绝。
- [ ] A 空间的 Agent 用 B 的 `X-Namespace` 看不到，也不能被 B 的用户执行。
