# M14 Kubernetes 多集群管理

通用规范见 [conventions.md](conventions.md)。

## 目标与依赖

在运维平台内接入多个 Kubernetes 集群：粘贴 kubeconfig 即可完成校验、探测和保存，集群列表展示接入状态；进入单个集群后可以查看和操作节点、工作负载、Pod 与 Ingress。依赖 M1 的租户与 RBAC。控制面仍然是 `alioth`，浏览器仍然只访问 Web。

## 范围与不做

做：

- 新增 `Cluster`，同一 Namespace 内可接入多个集群；名称在未删除记录上唯一。
- kubeconfig 只在接入、替换和探测时提交，服务端用 `ALIOTH_ENCRYPT_KEY` 派生的密钥加密后入库；任何接口都不回传原文。
- 接入时解析 kubeconfig、读取当前 context 的 API Server 与集群名，并探测一次 API Server 版本；探测失败不入库，返回可读的客户端错误。
- 集群列表、详情、改名/备注、替换 kubeconfig、删除、手动测试连通性。列表展示最近一次检测时间与最近错误。
- 基础资源管理：
  - 节点：状态、可调度、角色、内网 IP、kubelet 版本、OS、CPU/内存容量、Pod 数；cordon / uncordon。
  - 工作负载：Deployment、StatefulSet、DaemonSet 的副本与就绪情况、镜像；调整 Deployment/StatefulSet 副本数；滚动重启三种工作负载。
  - Pod：阶段、就绪、重启次数、节点、IP、所属控制器、容器；删除 Pod；读取容器日志尾部（最多 512 KiB）。
  - Ingress：IngressClass、主机、路径与后端服务、TLS Secret。
  - Namespace 列表，供页面筛选。
- 权限沿用租户 RBAC，但拆成两层：`cluster:read`、`cluster:write`、`cluster:delete` 只负责集群接入与连接（列表、详情、测试连通性、改 kubeconfig、删除集群），进入控制台仍要求 `cluster:read`；节点、工作负载、Pod 等资源按 `k8s:<资源>:<动作>` 独立授权，见下文「权限」。`owner`/`admin` 默认全部，`member`/`viewer` 默认只读。

不做：

- 不做任意 Kubernetes 对象的创建、编辑 YAML、删除（节点、Ingress、Namespace、CRD 等）。
- 不做 Pod exec / 终端、端口转发、文件拷贝、事件流和指标图表。
- 不把平台角色映射成集群内的 Kubernetes RBAC；集群凭据权限就是 kubeconfig 自身权限。
- 不做 Helm、GitOps、节点 drain、集群注册代理或 `alkaid` 转发。
- 不执行 kubeconfig 里的 exec 命令，也不读取 `tokenFile`、证书文件路径或 `proxy-url`。接入只接受内嵌的证书或 Token 数据，其它凭据来源直接拒绝；需要这类凭据时先用 `kubectl config view --raw` 导出内嵌数据再接入。

## 数据

| 实体 | 要点 |
| --- | --- |
| `Cluster` | `namespace_uid` + `name` 未删除唯一；`server`、`version`、`cluster_name`、`context_name`、`kubeconfig_cipher`（加密、`Sensitive`）、`remark`、`last_checked_at`、`last_error`；审计与软删除 |

- `kubeconfig_cipher` 与数据源凭据共用 `internal/data` 的加密盒；更换 `ALIOTH_ENCRYPT_KEY` 后旧集群需要重新接入。删除集群时同时清空 `kubeconfig_cipher`，记录只保留软删除元数据。
- 探测成功时写入 `version`、`server`、`cluster_name`、`context_name`、`last_checked_at`，并清空 `last_error`；探测失败时只更新 `last_checked_at` 和 `last_error`（接入阶段失败则不落库）。
- 集群客户端按 `cluster_uid` 进程内缓存；替换 kubeconfig 或删除集群时立即失效。缓存只保存 REST 配置和 clientset，不写数据库。
- 所有资源查询都先按当前 Namespace 校验集群归属，再使用该集群的凭据访问 API Server。跨租户的 `cluster_uid` 按不存在处理。

## 接口

集群接入与列表：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/v1/cluster` | 接入集群，先探测后入库 |
| `PUT` | `/v1/cluster/{uid}` | 更新名称/备注；`kubeconfig` 为空保持原值 |
| `DELETE` | `/v1/cluster/{uid}` | 删除集群与其凭据 |
| `GET` | `/v1/cluster/{uid}` | 集群详情 |
| `GET` | `/v1/clusters` | 分页列表，支持名称过滤 |
| `POST` | `/v1/cluster/{uid}/test` | 用已保存凭据测试并刷新检测结果 |
| `POST` | `/v1/cluster/probe` | 用尚未保存的 kubeconfig 测试，供接入表单预检 |

集群接入与连接的权限不变：列表、详情和测试连通性用 `cluster:read`；接入、更新与探测 kubeconfig 用 `cluster:write`；删除集群用 `cluster:delete`。

基础资源（路径中的 `{cluster_uid}` 均按当前租户校验）：

| 方法 | 路径 | 权限 |
| --- | --- | --- |
| `GET` | `/v1/cluster/{cluster_uid}/namespaces` | `cluster:read` |
| `GET` | `/v1/cluster/{cluster_uid}/nodes` | `k8s:node:read` |
| `PUT` | `/v1/cluster/{cluster_uid}/node/{name}/unschedulable` | `k8s:node:write` |
| `GET` | `/v1/cluster/{cluster_uid}/workloads` | `k8s:workload:read` |
| `PUT` | `/v1/cluster/{cluster_uid}/workload/scale` | `k8s:workload:write` |
| `POST` | `/v1/cluster/{cluster_uid}/workload/restart` | `k8s:workload:write` |
| `GET` | `/v1/cluster/{cluster_uid}/pods` | `k8s:pod:read` |
| `DELETE` | `/v1/cluster/{cluster_uid}/namespace/{namespace}/pod/{name}` | `k8s:pod:write` |
| `GET` | `/v1/cluster/{cluster_uid}/namespace/{namespace}/pod/{name}/logs` | `k8s:pod:logs` |
| `GET` | `/v1/cluster/{cluster_uid}/ingresses` | `k8s:ingress:read` |

- 列表分页参数沿用 `page` / `pageSize`，名称过滤用 `name`；Pod 与 Ingress 返回总数，节点和工作负载一次返回全部命中项。
- 命名空间和工作负载类型留空表示不限制。Pod 可按 `ownerKind` / `ownerName` 继续过滤，供工作负载下钻。
- kubeconfig、Secret、证书和 Token 不进入任何响应；服务端日志只记录错误类别，不打印凭据或上游响应体；Pod 日志在服务端截断到 512 KiB。

## 权限

`cluster:*` 只负责「接入与连接」：能看到集群、能测试连通性、能改 kubeconfig、能删集群；进入控制台仍要求 `cluster:read`。资源操作按资源独立授权，避免有集群权限的人自动看到 Secret 或删除 Pod。

| 权限 | 用途 |
| --- | --- |
| `cluster:read` | 查看集群列表/详情、测试连通性、进入控制台、读取 Namespace 列表 |
| `cluster:write` | 接入、更新、探测未保存的 kubeconfig |
| `cluster:delete` | 删除集群 |
| `k8s:node:read` / `k8s:node:write` | 查看节点 / cordon、uncordon |
| `k8s:workload:read` / `k8s:workload:write` | 查看 Deployment/StatefulSet/DaemonSet、镜像与历史版本 / 调整副本数、滚动重启、设置镜像、回滚 |
| `k8s:pod:read` / `k8s:pod:write` / `k8s:pod:logs` | 查看 Pod / 删除 Pod / 读取容器日志 |
| `k8s:ingress:read`、`k8s:service:read` | 查看 Ingress、Service 及其详情 |
| `k8s:configmap:read`、`k8s:secret:read` | 查看 ConfigMap、Secret 的键名与详情 |
| `k8s:pv:read`、`k8s:pvc:read` | 查看 PV、PVC |
| `k8s:job:read` / `k8s:job:write` | 查看 Job / 删除 Job |
| `k8s:cronjob:read` / `k8s:cronjob:write` | 查看 CronJob / 暂停、恢复、立即运行、删除 CronJob |

- YAML 预览按 `kind` 映射到对应资源的读权限：Node→`k8s:node:read`，Pod→`k8s:pod:read`，Deployment/StatefulSet/DaemonSet→`k8s:workload:read`，Job、CronJob、Ingress、Service、ConfigMap、Secret、PersistentVolume、PersistentVolumeClaim 各自对应。先校验 `kind` 再取权限，未知类型不会触达集群。
- 预置角色：`owner`、`admin` 拥有全部权限；`member`、`viewer` 拥有全部 `k8s:*:read` 和 `k8s:pod:logs`，没有任何 `k8s:*:write`。
- 自定义角色迁移：升级时，当前没有任何 `k8s:*` 权限的自定义角色按原有 `cluster:read`/`cluster:write` 一次性补齐对应的 k8s 读写（`cluster:read` 补全部读和 Pod 日志，`cluster:write` 补全部写）；补齐后不再命中，可重复执行。管理员可以继续在角色授权页按资源调整。
- 菜单和按钮按当前 Namespace 的权限生成，服务端仍然独立校验。

## 安全边界

- `cluster:write` 与 `k8s:*` 是租户管理员能力：持有者可以让 `alioth` 用已保存的 kubeconfig 访问任意可达的 API Server 地址（`cluster:write` 还能替换凭据本身）。这与数据源配置的信任模型一致，平台按内网使用设计；不要把集群操作权限授予不可信成员，也不要把管理台直接暴露到公网。
- 接入的 kubeconfig 只允许内嵌证书或 Token：服务端不会执行 `exec` / `auth-provider` 命令，也不读取 `tokenFile`、证书文件路径或 `proxy-url`，避免把租户输入变成控制面的命令执行或本机文件外带。
- 集群返回的 401/403 分别映射为“凭据被拒绝”和“凭据无权限”的客户端错误，不会清掉平台登录态，也不会触发 `/forbidden` 跳转。
- 删除集群会清空加密后的 kubeconfig；已保存的详情、列表和错误信息都不回传凭据原文。

## Web

- 「Kubernetes → 集群」列表页：名称、API Server、版本、最近检测/错误、备注和操作；接入弹窗填写名称、kubeconfig、备注，可先测试连接再保存；编辑时 kubeconfig 留空表示保持原值；删除需要确认；行操作为「详情 + 更多」。
- 集群详情页：头部展示集群元数据与测试连接；左侧资源导航分「节点、负载、服务与路由、配置管理、存储」，覆盖节点、Deployment/StatefulSet/DaemonSet、Pod、Ingress、Service、ConfigMap、Secret、PV、PVC。Tab、命名空间、类型、搜索词和页码写入 URL，刷新和前进后退保持一致；搜索面板默认收起；节点与 PV 不显示命名空间选择器。
- 节点提供 cordon/uncordon；工作负载提供副本数调整和滚动重启；Pod 提供删除和日志；九类资源都有详情抽屉，操作列统一使用全局「详情 + 更多」link 样式。
- 按 `web/AGENTS.md` 的滚动、表格、Tab 和 32px 表单控件约束实现，长内容只在指定面板内滚动。

## 验收标准

- [ ] 粘贴两个不同集群的 kubeconfig 后，集群列表出现两条记录，名称、API Server 与版本正确，任何接口响应都不含 kubeconfig 原文。
- [ ] 用错误的 kubeconfig 或不可达的 API Server 接入时返回客户端错误，列表不新增记录；编辑时 kubeconfig 留空不会清空原凭据。
- [ ] 带 `exec`、`tokenFile` 或证书文件路径的 kubeconfig 被拒绝，接入探测不会执行配置里的命令，也不会读取其指定的本机文件。
- [ ] 相同 Namespace 内重复名称被拒绝；不同 Namespace 可以使用相同名称，且互相看不到对方的集群。
- [ ] 未登录、无 `cluster:read` 的账号访问集群与资源接口被拒绝；无对应 `k8s:*:read` 的账号读该资源被拒绝；`viewer` 能看资源但不能 cordon、改副本、重启或删除 Pod。
- [ ] 节点列表能看到真实节点的状态、角色、IP、版本与 Pod 数；cordon 后节点变为不可调度，uncordon 后恢复。
- [ ] 工作负载列表覆盖三种类型；Deployment 调整副本数后实际 Pod 数变化；重启后 Pod 模板出现新的 `kubectl.kubernetes.io/restartedAt` 注解并滚动更新。
- [ ] Pod 列表能按命名空间和名称过滤（接口另支持按所属工作负载过滤），日志抽屉能切换容器、调整行数并读取上一条实例日志；删除 Pod 后列表刷新。
- [ ] Ingress 列表展示主机、路径、后端服务与 TLS；没有 Ingress 的集群返回空列表而不是错误。
- [ ] Service、ConfigMap、Secret、PV、PVC 列表返回真实数据；ConfigMap/Secret 只出现键名，接口响应与页面都不包含 Secret/ConfigMap 的值；PV 为集群级资源，不显示命名空间选择器。
- [ ] 九类资源行操作均为「详情 + 更多」link 样式；详情抽屉字段完整，工作负载展示副本集与 Pod 并可跳转，Ingress 关联 Service，Service 展示 Endpoints 与 `key=value` 选择器，ConfigMap/Secret/PVC 展示关联工作负载；标题无复制按钮；Secret/ConfigMap 的 YAML 值以 `<redacted>` 展示，响应和页面都不出现明文；名称筛选默认收起，展开后输入框与按钮同排对齐。
- [ ] `make migrate` 后新表生成，`cluster:*` 与 `k8s:*` 权限出现在权限目录并补入已有预置角色与自定义角色；`go test ./...`、`make lint`、Web 的 typecheck/lint/build 全部通过。

## 后续调整：详情页控制台化

详情页由四 Tab 改为「左侧资源导航 + 右侧资源面板」，导航按负载 / 服务与路由 / 配置管理 / 存储 分组，命名空间切换统一写进 URL 并驱动所有命名空间级列表；节点与 PV 作为集群级资源不再显示命名空间选择器和提示。默认视图仍是节点，`tab` / `kind` / `namespace` / `name` / `page` / `pageSize` 的 URL 语义保持兼容；搜索面板默认收起，操作列统一为「详情 + 更多」。

九类资源都有列表和详情抽屉，抽屉用「详细信息 / YAML」双 Tab，并按资源展示副本集/Pod、关联 Service、Endpoints、关联工作负载等关系数据；详细信息按资源分组并支持复制，YAML 代码块铺满剩余高度、内部滚动、GitHub light/dark 高亮（Secret/ConfigMap 值脱敏）；Service、ConfigMap、Secret、PV、PVC 已由新增的只读列表接口提供真实数据（Secret/ConfigMap 仅键名）。概况大盘复用 nodes / workloads / pods / ingresses 在浏览器侧汇总；指标用量和真实控制面状态仍需要后续接入指标数据源。页面结构、组件拆分、视觉规范、接口清单与后续增强见 [../kubernetes-console-design.md](../kubernetes-console-design.md)。
