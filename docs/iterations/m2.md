# M2 告警配置

通用规范见 [conventions.md](conventions.md)。

## 目标与依赖

租户可以维护数据源、告警字典和规则。这一步不运行评测。

依赖：M1。

## 范围与不做

做：三种数据源的管理与查询、规则组、规则、级别条件、对应页面。

不做：`megrez` 评测循环、`AlertEvent`、通知任务。Logs 与 Trace 可以保存和查询，不产生评测批次。不实现短信。不把 Redis 用于规则缓存。

## 开发细则

### 数据

在 `alioth` 增加：

| 实体 | 要点 |
| --- | --- |
| `Datasource` | 类型、驱动、连接信息、启停、数据源级别。归属 Namespace |
| `AlertDictionary` | 名称、展示色。区分告警级别与数据源级别，对应 Moon 的 `LEVEL_TYPE_ALERT` 与 `LEVEL_TYPE_DATASOURCE` |
| `AlertRuleGroup` | Namespace 内唯一名称，可启停 |
| `AlertRule` | 属于一个组，带类型与驱动，可启停，保存指标表达式、标签、数据源过滤、摘要、描述 |
| `AlertRuleLevel` | 比较条件、采样方式、阈值、持续秒数，指向 `AlertDictionary` |

类型与驱动使用 Moon 已有枚举：

| 类型 | 驱动 |
| --- | --- |
| METRICS | METRICS_PROMETHEUS、METRICS_VICTORIA_METRICS |
| LOGS | LOGS_ELASTICSEARCH、LOGS_LOKI、LOGS_VLOGS |
| TRACE | TRACE_JAEGER |

比较条件：EQ、NE、GT、GTE、LT、LTE、IN、NOT_IN。采样：FOR、MAX、MIN。

连接密码和密钥经加密字段入库。读接口不返回明文。

同一 Namespace 内，数据源、规则组、规则、级别的名称在未删除记录上唯一。

### 接口行为

资源对应 Moon marksman 的数据源、策略组、策略、指标条件和级别。Alioth 的资源名是 Datasource、AlertRuleGroup、AlertRule、AlertRuleLevel、AlertDictionary。URL 在 `api/alioth/v1` 定稿。

需要具备的行为：

- 数据源的创建、更新、启停、删除、详情、列表、下拉选择
- 指标数据源的状态、指标列表、指标详情。VictoriaMetrics 的指标名从标签值接口读取，指标详情从 series 接口读取
- 即时查询、区间查询、代理查询。对应 Moon 的 `query`、`query_range`、`proxy`
- 数据源地址支持路径前缀，VictoriaMetrics 集群的 `/select/<accountID>/prometheus` 无需拆成单独字段
- Logs 与 Trace 的查询代理只转发到对应驱动，不写入评测批次
- Loki、VictoriaLogs 和 Elasticsearch 日志数据源支持连通检查与日志区间查询；Elasticsearch 的索引模式和时间字段随数据源保存
- 数据源列表和详情展示驱动产品图标；元数据页区分指标元数据、Loki 构建信息、VictoriaLogs 健康状态以及 Elasticsearch 集群状态和节点分配
- 规则组与规则的创建、更新、启停、删除、列表
- 为规则保存指标定义和级别阈值
- 告警字典的创建、更新、启停、删除、列表

写操作要求 `datasource:write` 或 `alert_rule:write`。`viewer` 只有读。停用的规则打上停用状态，调度候选查询必须排除它们。本步可以提供这个查询给后续 `megrez` 使用，但不启动评测循环。

保存 Logs 或 Trace 规则时只写规则表。不写 `AlertEvent`，不写评测批次。

### Web

- 数据源：左侧列表，右侧为详情、元数据和查询。指标查询区提供表达式编辑，交互对应 Moon Web 的 PromQL 快查。
- 规则：左侧规则组，右侧规则列表和编辑。编辑保存表达式、级别条件和持续秒数。通知组的绑定不在规则上实现；M8 起由告警订阅负责路由。
- 告警字典：列表、新建、编辑、启停。

筛选和分页走 URL 查询参数。启停在列表行内完成。

## 本步规范

- 数据源客户端放在 `alioth` 的 `data`。`service` 不直接拼 Prometheus 或 Elasticsearch 的 HTTP。
- 查询代理设置超时。超时返回服务端错误，不把上游堆栈返回给浏览器。
- 加密与解密放在存储层。biz 看到的是明文配置，日志里打码。
- 规则是否参与评测只看数据库状态。不在 `megrez` 进程里另存一份启用名单。

## 验收标准

- [ ] 使用具备 `datasource:write` 的账号，在 `http://<web>:8080` 保存 Prometheus 或 VictoriaMetrics、Elasticsearch、Jaeger 三种数据源。
- [ ] 数据库中的数据源密码和密钥不是明文。页面回显不包含明文密钥。
- [ ] `viewer` 可以打开数据源和规则列表，创建与启停被拒绝。
- [ ] 对指标数据源执行即时查询和区间查询，结果出现在页面上。
- [ ] Logs 与 Trace 数据源可以保存，查询代理有成功或明确的上游错误；Loki 与 Elasticsearch 的日志查询返回原始 JSON。保存一条 Logs 或 Trace 规则后，库里没有评测批次，也没有 `AlertEvent`。
- [ ] 停用的规则不在到期候选集合中。重新启用后出现。
- [ ] 同一 Namespace 内规则组重名被拒绝。另一个 Namespace 可以使用同名。
- [ ] 缺少 `X-Namespace` 的写请求被拒绝。A 空间的数据源用 B 的请求头读取不到。
