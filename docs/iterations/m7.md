# M7 多副本部署

通用规范见 [conventions.md](conventions.md)。

## 目标与依赖

控制面和两个工作进程以多副本运行。集群外仍然只有 Web。摇光可以按 systemd 或 Kubernetes 安装。

依赖：M3、M4、M6。

## 范围与不做

做：`web`、`alioth`、`megrez`、`merak` 的 Deployment，PostgreSQL 与 Redis 的独立部署，`alkaid` 的 systemd 单元和 Kubernetes 安装说明。

不做：为 `megrez`、`merak`、`alkaid` 建业务库。不把 Redis 持久化成业务数据的来源。不把 8000、8001、8002、8022、9000、9022 发布到集群外。不在这一步增加新的产品功能。

## 开发细则

### 控制面与工作进程

为以下进程提供 Deployment，副本数至少为 2：

| 进程 | 探针 | 对外 Service |
| --- | --- | --- |
| `web` | HTTP 8080 | 集群外只发布这个 Service |
| `alioth` | HTTP 8000 `/health`，gRPC 9000 仅集群内 | 不发布到集群外 |
| `megrez` | HTTP 8001 `/health` | 不发布到集群外 |
| `merak` | HTTP 8002 `/health` | 不发布到集群外 |

PostgreSQL 与 Redis 使用独立的部署或外部实例。连接串用环境变量注入。Redis 不开启业务持久化要求；锁丢失后由 TTL 和数据库唯一约束收口，不把 Redis 的 RDB 当作告警记录。

`web` 的 nginx 配置把 `/v1` 转到 `alioth` 的集群内地址 8000。配置里不出现 `megrez`、`merak`、`alkaid` 的上游。

滚动更新时允许同时存在新旧副本。登录状态在 JWT 里，不要求粘性会话。

### 摇光

提供两种安装方式：

- systemd：单元文件、环境文件示例。环境文件包含 `alioth` 的 gRPC 地址和 Agent 令牌。进程监听 8022 与 9022，并出站连接 `alioth:9000`。
- Kubernetes：Deployment。需要访问节点文件时改为 DaemonSet，并在说明里写明选择条件。集群内访问 API Server 时使用 ServiceAccount。

两种方式都不要求控制面回拨 Agent。

### 安全收口

部署清单不包含明文密码。数据源密钥、渠道密钥和用户密码沿用前面里程碑的存储规则，在运行中的库里抽查。

审计删除接口保持关闭，或对 `member` 与 `viewer` 返回无权限。`owner` 与 `admin` 是否允许删除审计，以设计文档为准：普通成员不能删除。本步不新增删除入口。

## 本步规范

- 副本数写在清单里，不靠手工起第二个进程作为唯一证明。验收使用清单部署的结果。
- 健康检查失败的副本不得留在 Service 端点里。
- `alkaid` 的令牌通过 Secret 或 root 只读的环境文件注入，不写进镜像。
- 文档中的地址使用服务名和本文端口，不写某台开发机的临时 IP 作为默认值。

## 验收标准

- [ ] `web`、`alioth`、`megrez`、`merak` 的就绪副本都不少于 2。
- [ ] 停掉其中一个 `alioth` 副本后，经 `http://<web>:8080` 的登录和个人资料仍然成功。
- [ ] 停掉其中一个 `megrez` 副本后，到期指标规则仍能产生或恢复告警。
- [ ] 停掉其中一个 `merak` 副本后，PENDING 任务仍能发出。
- [ ] 从集群外只能访问 `web` 的 8080。8000、8001、8002、8022、9000、9022 都不可达。
- [ ] 集群内可以访问 `megrez:8001/health` 和 `merak:8002/health`。
- [ ] 按 systemd 说明安装一台 `alkaid`，按 Kubernetes 说明安装一个 `alkaid`。两者都出站注册到 `alioth:9000`，机器页显示在线。
- [ ] 抽查一条数据源密钥、一条渠道密钥和一条用户记录，库里没有明文密码。`member` 与 `viewer` 不能删除 SSH、SFTP、Kubernetes 审计。
