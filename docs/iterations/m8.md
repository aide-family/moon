# M8 通知增强

通用规范见 [conventions.md](conventions.md)。

## 目标与依赖

补齐试发结果提示、通知组的成员与 Webhook 选择，并把规则直接绑定通知组改为告警事件订阅。依赖 M4。

## 范围与不做

做：

- 渠道试发和模板试发提交后提示“试发任务已创建”。
- 通知组选择当前 Namespace 的成员和多个 Webhook 渠道，选择 Webhook 时指定一个 WEBHOOK 模板。
- 新增 `NotificationSubscription`，按标签、告警级别和数据源匹配事件，发送给订阅下的通知组。
- 移除 `AlertRule` 到 `NotificationGroup` 的直接绑定及相关页面、查询和测试。
- “我的告警”改为按订阅下的通知组成员和实际通知任务判断。

不做：

- 试发不做同步等待，也不轮询投递结果；只提示任务已创建，结果仍在消息日志查看。
- 不按每个 Webhook 单独配置模板；同一通知组的 Webhook 共用一个模板。
- 不允许跨 Namespace 选择成员、渠道或通知组。

## 开发细则

### 数据

| 实体 | 要点 |
| --- | --- |
| `NotificationGroup` | 新增 `member_uids`、`webhook_channel_uids`、`webhook_template_uid`。成员只保存当前 Namespace 的成员标识 |
| `NotificationSubscription` | 名称、状态、标签匹配器、告警级别、数据源、备注 |
| `NotificationSubscriptionGroup` | 订阅到通知组的绑定，唯一约束 `(subscription_uid, group_uid)` |
| `NotificationTask` | 新增 `subscription_uid`；去重索引改为 `(event_uid, phase, group_uid, channel_uid)` |

`alert_rule_notification_groups` 在迁移中删除。旧绑定不再保留。

### 投递

- 评测回写 FIRING 或自动恢复时，在同一事务内匹配启用的订阅。
- 标签使用包含匹配；告警级别和数据源为空表示不限制；条件之间是 AND。
- 同一通知组被多个订阅命中时只保留首个订阅标识；同一事件、组、渠道只生成一条任务。
- 通知组主渠道生成一条任务，每个选中的 Webhook 渠道各生成一条任务。
- SMTP 主渠道的接收方由手填邮箱和成员邮箱合并去重；成员被移除或封禁时跳过。
- 停用的订阅、通知组、渠道或模板不产生任务。

### Web

- 通知组表单增加成员多选、Webhook 渠道多选和 Webhook 模板选择。
- 新增“通知 → 告警订阅”页面，支持增删改查和启停。
- 移除规则编辑页的通知组选择。
- 试发成功提交后使用 Toast 提示“试发任务已创建”。

## 验收标准

- [ ] 渠道试发和模板试发点击发送后出现“试发任务已创建”提示，消息日志中能看到对应任务。
- [ ] 通知组能选择当前租户成员；成员邮箱参与 SMTP 投递，未加入或已封禁成员不投递。
- [ ] 通知组能选择多个 Webhook 渠道；每个渠道各生成一条任务，且使用 Webhook 模板。
- [ ] 规则编辑页不再出现通知组选择；`AlertRule` 接口不再返回通知组字段。
- [ ] 订阅按标签、告警级别、数据源匹配；任一条件不满足时不发送。
- [ ] 多个订阅命中同一通知组时只产生一条通知；同一事件、组、渠道只有一条任务。
- [ ] 停用订阅或通知组后，不再产生新任务。
- [ ] `alert_rule_notification_groups` 不再被查询，迁移后旧表被删除。
