# M24 租户菜单、渠道能力细化与账号治理

M24 在 M23 的升级迁移能力之上补六项租户运营与账号治理改动：**租户功能在侧边栏独立成组**，**通知渠道能力按应用与提供商细化**，**成员不再有系统预置角色且授权不允许越权**，**平台可以删除错误用户**，**OAuth 补邮箱命中已有账号时按邮箱账号为母本全量合并**。不改评测与投递语义，也不实现短信发送。

依赖：M19（能力模型）、M20（套餐与订单）、M21（类型级能力）、M22（权益快照与菜单化授权）、M23（升级迁移）。

## 1. 租户功能独立成组

「系统管理」现在同时放着平台页和租户页，菜单语义混乱。改为：

- 新增侧边栏分组「租户」（`nav.tenantSpace`），包含**我的租户**（`/namespaces`）、**订单**（`/orders`）、**成员**（`/members`）、**角色**（`/roles`）四个入口；
- 「系统管理」只保留平台级页面：租户管理（`/tenants`）、套餐管理、用户、后台工作进程、升级与迁移；
- 我的租户和订单不依赖当前租户权限，没有加入任何租户的用户也保留入口；成员和角色仍按 `menu:<能力>` + 租户能力 + 资源权限三重判定；
- 系统管理分组没有可见入口时不渲染，普通租户用户不会看到空分组。

## 2. 通知渠道能力按应用 / 提供商细化

Webhook 渠道不再是一个笼统能力，按应用拆成四个能力；短信渠道按提供商拆成两个能力：

| 渠道 | 应用 | 能力编码 |
| --- | --- | --- |
| SMTP | OTHER | `notify_channel_smtp`（不变） |
| WEBHOOK | OTHER（自定义 Webhook） | `notify_channel_webhook_other` |
| WEBHOOK | DINGTALK | `notify_channel_webhook_dingtalk` |
| WEBHOOK | WECHAT | `notify_channel_webhook_wechat` |
| WEBHOOK | FEISHU | `notify_channel_webhook_feishu` |
| SMS | SMS_ALICLOUD | `notify_channel_sms_alicloud` |
| SMS | SMS_TENCENT | `notify_channel_sms_tencent` |

约束：

- 能力目录（后端 `app/alioth/pkg/perm` 与 Web 静态目录）同步；通知渠道菜单由这七个能力共同开通。
- 渠道的创建、修改、删除、列表、下拉和试发都按「渠道类型 + 应用」校验与过滤；模板按类型与应用过滤（EMAIL 需要 SMTP，WEBHOOK 模板的 app 必须是已授权应用，SMS_ALICLOUD 需要阿里云短信能力）。
- 通知组只返回已授权渠道与模板；保存时逐对校验渠道与模板能力，未授权组合拒绝。
- 腾讯云短信只作为可售能力进目录，本期**不做渠道表单、不做模板类型、不做发送**；短信发送仍以明确原因失败。
- 通知组新建 / 编辑按能力渲染分区：只有开通 SMTP 才出现邮件分区，只有开通阿里云短信才出现短信分区，每个 Webhook 应用只在开通对应能力时出现。**未授权短信渠道时不再渲染短信表单**，也不再提交空的短信字段。
- seed 迁移把旧能力展开成新能力：`notify_channel_webhook` → 4 个应用能力，`notify_channel_sms` → 2 个提供商能力，更旧的模块级 `notify_channel` → 全部 7 个渠道能力；套餐明细、租户额外能力和租户套餐能力快照（`namespaces.package_features`）都处理，可重复执行。读取路径同样归一化，旧快照不会因为编码过时而丢能力。

## 3. 移除成员预置角色与越权限制

**角色完全由租户创建，成员添加时显式分配。** 新租户不再自动创建 `owner`、`admin`、`member`、`viewer` 四个预置角色；存量租户的预置系统角色及其成员授权、权限授权由 seed 迁移删除（`role.is_system = true` 的行）。自定义角色保持不变。

**负责人权限改为隐式判定**：`namespaces.owner_uid` 对应当前用户时，该用户拥有这个租户的全部租户权限（含所有已开通能力的菜单权限，即 `perm.Names()`），不再依赖 owner 角色；负责人权限仍受套餐能力与模块开通限制。`/self/permissions` 对负责人返回完整权限集合，前端据此展示按钮。

**不允许越权**（非负责人）：

- 持有 `role:write` 的用户更新角色权限时，只能授予自己当前拥有的权限；`normalizeRoleGrant` 补出的菜单权限和默认读权限也必须落在自己的权限集合内；
- 邀请成员、给成员分配角色时，只能分配「角色权限 ⊆ 自己权限」的角色；
- 负责人不受子集限制，但仍受租户已开通能力范围限制。

其它随之简化的行为：移交负责人只修改 `namespace.owner_uid`（目标必须是 JOINED 成员），不再增删 owner/admin 角色；成员邀请不再拒绝名为 owner 的角色；套餐升级 / 续期 / 同步授权不再给预置角色补权限（已无预置角色）。

**升级影响**：存量租户里只持有预置角色的成员会失去这些角色，需要由租户负责人重新创建角色并分配；租户负责人不受影响（隐式权限）。这是本次模型切换的预期结果。

## 4. 用户删除

新增 `DELETE /v1/user/{uid}`（`system:user:write`，与封禁同一权限），用于清理错误数据（重复账号、OAuth 占位账号等）。

- 拒绝：删除自己、删除平台超级管理员、删除仍是任一未删除租户负责人的用户、删除还有租户订单的用户；错误信息说明原因。
- 通过后在一个事务里软删用户，并清理其第三方绑定、成员与成员角色、告警页个人选择、告警列配置、系统消息、邀请记录；保留其创建过的租户告警页面（租户配置不随账号删除）。
- Web 用户列表的行操作增加「删除」，确认弹窗写明不可恢复；删除后刷新列表。

## 5. OAuth 绑定邮箱命中已有账号时的全量合并

历史版本给 OAuth 账号发占位邮箱（`@users.alioth.local`）时，补真实邮箱若命中了已有账号，只迁移了成员、角色、租户负责人和平台角色，个人数据留在空账号上。

M24 把 `MergeAccounts` 扩展为**以已存在的邮箱账号为母本的全量合并**：

- 迁移源账号的全部个人数据到邮箱账号：创建的租户告警页面归属、实时告警页选择、告警列配置、系统消息、租户订单、成员邀请（被邀请人与邀请人）、第三方绑定，以及通知组里引用成员的 UID 列表；目标已有冲突行时保留目标、丢弃源行（按各自唯一键去重）。
- 目标是母本：源账号的非空字段只在目标为空时补齐（手机号、头像、备注等），不覆盖目标已有值；邮箱、名称、昵称、状态和平台角色保持目标已有语义。
- 合并与软删源账号在同一个事务内完成；重复提交、并发提交和源账号已软删都按幂等处理，不产生 500。绑定迁移仍由后续 `MoveOAuth` 完成。

## 6. 租户能力快照的兼容与保存语义

通知渠道能力拆分暴露了两个存量数据问题，本步一起修掉：

- `namespaces.package_features` 是在 M21 类型拆分之后引入的，M24 再拆通知渠道时，存量快照仍可能保存 `notify_channel_webhook` / `notify_channel_sms`。读取路径（`capabilityCodesOf`）统一用 `perm.NormalizeCapabilities` 归一化：历史类型编码展开成新的应用/提供商能力，模块编码展开成模块全部能力，未知编码忽略。seed 新增 `migratePackageFeatureSnapshots` 把库里的旧快照改写为当前编码（可重复执行），基础套餐缺失的能力仍由 `ensureBasePackage` 补齐。
- 租户功能授权保存的必含项改为**租户当前的套餐快照**（M22 的权益快照语义），不再是套餐的最新明细：管理员后来给套餐新增能力，不会让已生效租户的保存被反向卡住；换套餐时才按新套餐当前明细要求。旧客户端提交的历史渠道编码会先展开成当前能力再比较，不会因为同义编码被判定缺能力。

## 验收

1. 侧边栏出现独立「租户」分组（我的租户 / 订单 / 成员 / 角色）；系统管理只剩平台级入口；没有租户权限的用户仍能看到我的租户和订单。
2. 套餐能力勾选页出现 4 个 Webhook 应用能力与 2 个短信提供商能力；只开通 SMTP 的租户，渠道页只有 SMTP，模板页只有 EMAIL；只开通钉钉 Webhook 的租户，只能创建 / 查看钉钉 Webhook 渠道与钉钉 / 通用 Webhook 模板。
3. 未授权短信渠道时，通知组新建 / 编辑不出现短信表单；授权阿里云短信后出现短信分区；保存通知组时未授权渠道或模板组合被服务端拒绝。
4. 新建租户后角色列表为空；负责人无需角色即可看到并操作全部已开通能力内的菜单与接口；负责人可创建角色、邀请成员并分配角色。
5. 非负责人即使持有 `role:write`，更新角色权限、邀请成员或分配角色时都无法授予自己没有的权限（接口拒绝并返回明确原因）。
6. 存量租户 seed 升级后预置系统角色及其授权被删除，自定义角色保留；seed 可重复执行。
7. 平台管理员可以删除错误用户；删除自己、超级管理员、租户负责人和有订单的用户被拒绝并给出原因；删除后用户不再出现在用户列表，成员与个人配置被清理。
8. OAuth 账号补邮箱命中已有账号后，源账号的告警页选择、列配置、系统消息、订单、邀请与第三方绑定都出现在邮箱账号上，源账号被软删；重复提交不报错。
9. 存量租户的套餐快照里含 `notify_channel_webhook` / `notify_channel_sms` 时，功能授权状态与有效能力展示 4 个 Webhook 应用能力和 2 个短信提供商能力；保存租户功能授权成功，seed 会把快照归一化写回。管理员给套餐新增能力后，已生效租户仍能保存自己快照范围内的授权，不会被套餐最新明细反向卡住。
10. `go vet`、后端单元测试、相关真库集成测试、`gofmt`、`check-naming`、`buf lint`、`make wire`、web typecheck / lint / build 通过。
