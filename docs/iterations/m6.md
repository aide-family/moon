# M6 SFTP 与 Kubernetes 代理

通用规范见 [conventions.md](conventions.md)。

## 目标与依赖

在 M5 的出站流上增加文件操作和 Kubernetes API 转发，并留下审计。

依赖：M5。

## 范围与不做

做：SFTP 的列目录、上传、下载、建目录、删除；经 Agent 转发的 Kubernetes API；两类审计；对应页面。

不做：把文件保存在玉衡磁盘。不做对公网开放的代理端口。不让 Agent 令牌绕过用户权限。不实现探测任务。

## 开发细则

### 数据

在 `alioth` 增加：

| 实体 | 要点 |
| --- | --- |
| `SFTPAudit` | 操作者、Agent、路径、动作、结果 |
| `K8sProxyAudit` | 操作者、Agent、动词、资源、命名空间、结果 |

审计只追加。`member` 和 `viewer` 不能删除。

### SFTP

帧走已有的 Agent 流。`alioth` 在转发前检查权限：

| 权限 | 允许的动作 |
| --- | --- |
| `sftp:read` | 列目录、下载 |
| `sftp:write` | 上传、建目录、删除 |

只有读权限时，写动作返回无权限。文件字节从浏览器到 Web，到 `alioth`，再到 Agent，最后到目标主机。`alioth` 不把内容写入本地文件或对象存储。临时缓冲若使用内存或临时文件，请求结束后删除，验收时玉衡磁盘上找不到该文件。

每次操作写一条 `SFTPAudit`。失败也写，结果字段标明失败原因。目标 Agent 离线时立即失败，不排队。

### Kubernetes 代理

Agent 使用挂载的 kubeconfig，或在集群内使用 ServiceAccount。浏览器和 `megrez` 都不直连 API Server。

路径：浏览器到 `web:8080`，到 `alioth:8000`，到该 Agent 的流，到 API Server。`alioth` 检查 `k8s:proxy`，先写审计再转发。没有权限时不把请求送进流。

Agent 令牌不能调用这条用户侧的代理接口。代理不监听新的公网端口，仍使用 `alioth` 已有的 HTTP。

离线 Agent 的代理请求立即失败。

### Web

SFTP 页面：选择在线 Agent，浏览目录，执行上传、下载、建目录和删除。没有对应权限的按钮不展示，接口仍自行校验。

Kubernetes 代理页面：选择在线 Agent，发起受控的 API 请求，并展示审计。页面不提供任意 TCP 隧道。

## 本步规范

- 权限检查在 `alioth` 的 biz，在字节转发之前完成。
- 审计与转发在同一请求里。转发发生之前审计行已经插入；转发结果回来后更新结果字段。
- 下载响应不缓存到 `web` 的静态目录。
- kubeconfig 加密存放或只存在于 Agent 侧。若由 `alioth` 下发，日志中打码。

## 验收标准

- [ ] 只有 `sftp:read` 的用户可以列目录和下载。上传、建目录、删除被拒绝。加上 `sftp:write` 后这三项成功。
- [ ] 每次 SFTP 操作都有 `SFTPAudit`，含操作者、Agent、路径、动作和结果。失败操作也有记录。
- [ ] 上传一个文件后再下载，内容一致。玉衡磁盘上没有该文件的副本。
- [ ] 没有 `k8s:proxy` 的用户转发被拒绝，且请求没有到达 API Server。有权限时请求到达 API Server，`K8sProxyAudit` 含操作者、动词、资源和命名空间。
- [ ] 用 Agent 令牌调用代理接口被拒绝。
- [ ] Agent 离线时，SFTP 和代理都立即失败。
- [ ] 在 `http://<web>:8080` 完成一次列目录和一次只读的 Kubernetes 查询。集群外仍然访问不到 8022 和 9022。
